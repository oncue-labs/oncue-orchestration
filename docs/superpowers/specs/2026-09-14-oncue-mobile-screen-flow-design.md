# OnCue 모바일 MVP 화면 흐름 사양

## 목적

사용자가 제공된 통화 조합을 확인하고 예약·수정하며, 예약된 통화를 iOS 시스템 수신 전화 화면으로 받을 수 있도록 모바일 화면의 책임과 이동 흐름을 정의한다.

이 문서는 Flutter 앱 화면과 iOS 시스템 통화 화면의 경계를 정한다. 백엔드 API와 보이스 서버 계약은 변경하지 않는다.

## 화면 흐름

```text
로그인
  ↓
통화 조합 목록
  ↓
통화 조합 상세 및 예약
  ↓
예약 목록
  ↓
예약 상세 ──→ 예약 수정
```

예약 생성 전에 필수 통화 권한 또는 플랫폼 설정이 준비되지 않았으면 예약 API를 호출하지 않고 권한 안내 화면으로 이동한다.

예약 시각이 되면 앱은 PushKit payload를 받아 iOS에 통화를 등록한다. 수신·통화 중 화면은 Flutter가 직접 그리지 않고 iOS CallKit 시스템 화면이 표시한다.

## 화면별 책임

### 로그인

- Kakao 또는 X 로그인을 제공한다.
- 로그인 성공 후 통화 조합 목록으로 이동한다.
- access token은 앱 내부 인증 저장소에서 관리하고 화면에 표시하지 않는다.

### 통화 조합 목록

- 제공자가 정의한 MVP 통화 조합을 카드로 표시한다.
- 카드에는 페르소나 이미지, 페르소나 이름, 짧은 시나리오 설명을 표시한다.
- 긴 시나리오 설명은 말줄임표로 축약한다.
- 카드 선택 시 해당 통화 조합 상세 화면으로 이동한다.
- UI는 추천 조합을 표시하지만 API 요청에서는 `personaKey`와 `scenarioKey`를 각각 전달한다.

### 통화 조합 상세 및 예약

- 통화 조합의 페르소나 이미지와 이름을 표시한다.
- 약 10초 길이의 음성 미리듣기를 제공한다.
- 전체 시나리오 설명을 표시한다.
- `시나리오 컨텍스트` 입력란 하나와 `통화 목표` 입력란 하나를 제공한다.
- 시나리오 컨텍스트 placeholder에는 해당 시나리오에서 자연스러운 대화에 도움이 되는 입력 예시를 간략히 안내한다.
- 예약 시각과 기기 time zone을 입력받는다.
- 예약 시각은 정확한 수신 시각이 아니라 예상 시각임을 표시한다.
- 예약 API 호출 전 `CallPermissionService`로 필수 통화 권한·플랫폼 설정을 확인한다.
- 안전성·시나리오 범위 판단은 모바일에서 수행하지 않는다.

### 권한 안내

- 예약에 필요한 통화 권한 또는 플랫폼 설정이 준비되지 않은 경우에만 표시한다.
- 누락된 권한과 설정 목적을 사용자에게 설명한다.
- 권한 요청 또는 시스템 설정 화면 이동을 제공한다.
- 준비가 완료되면 이전 예약 화면으로 돌아간다.

### 예약 목록

- 로그인한 사용자의 예약 통화 목록을 표시한다.
- 각 항목에 통화 조합, 페르소나 이미지, 예약 시각, 예약 상태를 표시한다.
- 항목 선택 시 예약 상세 화면으로 이동한다.

### 예약 상세

- 통화 조합과 페르소나 이미지를 표시한다.
- 예약 시각, time zone, 예상 시각 안내를 표시한다.
- 시나리오 컨텍스트와 통화 목표를 표시한다.
- `reservationStatus`, `callStatus`, `callOutcome`을 구분해 표시한다.
- `callOutcome`이 없으면 통화 진행 중으로 표시하고, 값이 있으면 통화가 종료된 것으로 표시한다.
- `editableUntil`이 지나면 예약 수정·취소 동작을 비활성화하고 다음 문구를 표시한다.

  `통화 5분 전부터는 예약을 수정할 수 없습니다.`

- `voiceSessionId`, 정책 스냅샷, 내부 오류 정보는 표시하지 않는다.
- 통화가 종료된 뒤에는 통화 결과를 표시한다.

### 예약 수정

- 예약 생성 화면과 같은 입력 구성요소를 재사용한다.
- 수정 가능한 값은 통화 조합, 시나리오 컨텍스트, 통화 목표, 예약 시각이다.
- 수정 API 호출 전 권한과 입력값을 확인한다.
- 수정 중 마감 시간이 지나거나 백엔드 검증이 실패하면 오류를 표시하고 사용자가 입력한 값은 유지한다.
- 백엔드가 반환한 `editableUntil`을 기준으로 수정 가능 여부를 판단한다.

## iOS 시스템 통화 화면

- PushKit 수신 후 Flutter 화면을 먼저 띄우지 않고 CallKit에 수신 통화를 등록한다.
- 잠금·백그라운드 상태에서도 iOS가 제공하는 시스템 수신 전화 화면을 사용한다.
- 시스템 화면에는 Push payload의 안전한 표시 이름만 사용한다.
- 사용자가 응답하기 전에는 WebRTC 연결 토큰을 요청하지 않는다.
- 사용자가 응답하면 앱은 백엔드에서 1회성 연결 토큰을 받은 뒤 보이스 서버와 WebRTC 연결을 시작한다.
- 사용자가 거절·종료하면 시스템 이벤트를 공통 `SystemCallManager` 계약으로 전달한다.
- Flutter에서 별도의 수신 전화·연결 중·통화 중 화면을 MVP에 만들지 않는다.

## 상태 표시 원칙

사용자에게 보여줄 값은 예약 상태, 통화 진행 상태, 통화 결과로 제한한다.

| 영역 | 표시 값의 역할 |
| --- | --- |
| `reservationStatus` | 예약이 등록·취소·수정 가능한지 표시 |
| `callStatus` | 통화가 준비·수신 대기·연결·통화 중 어느 단계인지 표시 |
| `callOutcome` | 통화가 성공 또는 실패로 종료됐는지 표시 |

통화 준비, 시그널링, WebRTC 내부 오류의 상세값은 예약 상세 화면에 노출하지 않고 백엔드 응답의 사용자용 오류 문구만 표시한다.

## MVP 제외 범위

- Android 전용 화면과 native 통화 구현
- 사용자가 직접 페르소나·시나리오를 생성하는 화면
- 관리자가 페르소나를 등록하는 페이지
- 반복 예약
- 사용자 임의 수신자 지정
- Flutter에서 직접 그린 수신 전화 화면
- 통화 중 별도 커스텀 화면

## 완료 기준

- 로그인 후 통화 조합 목록에서 카드 하나를 선택할 수 있다.
- 상세 화면에서 이미지·10초 미리듣기·시나리오 설명·두 입력란·예약 시각을 확인할 수 있다.
- 권한이 준비되지 않으면 예약 API가 호출되지 않고 권한 안내 화면이 표시된다.
- 예약 목록에서 상세·수정 화면으로 이동할 수 있다.
- 수정 마감 후에는 수정·취소가 비활성화된다.
- iOS 수신 통화는 Flutter 커스텀 화면이 아니라 CallKit 시스템 화면으로 표시된다.
