# OnCue MVP 설계 사양

## 1. 목적

OnCue는 사용자가 제공된 통화 조합을 선택하고 시나리오 컨텍스트와 통화 목표를 입력하면, 지정한 현지 시간 무렵에 선택한 페르소나가 iOS 앱 사용자에게 먼저 전화를 걸어 제한된 시나리오 기반 대화를 제공하는 서비스다.

MVP는 iOS를 먼저 지원하며, 앱이 백그라운드 또는 잠금 상태여도 CallKit 기반 수신 전화 경험을 제공한다. 실제 통화 음성은 모바일과 `oncue-voice` 사이의 WebRTC로 전달하고, 사용자·예약·대화 정책은 `oncue-backend`가 관리한다.

## 2. MVP 범위

### 제공 통화 조합

MVP에는 다음 네 가지 통화 조합을 제공한다.

- 산타 + 어린이 역할놀이
- 공주 + 어린이 역할놀이
- 친구 + 귀가 유도 전화
- 여행 동행 친구 + 부모님 소개

페르소나와 시나리오는 서로 독립적으로 관리한다. 하나의 통화 조합은 항상 페르소나 하나와 시나리오 하나로 구성되며, 하나의 페르소나나 시나리오는 여러 조합에 사용될 수 있다. 사용자 화면에서는 제공자가 추천하는 통화 조합을 보여줄 수 있지만, API 요청에서는 안정적인 `personaKey`와 `scenarioKey`를 별도로 전달한다. 백엔드는 두 key의 조합을 별도 허용 목록으로 검증하지 않고, 각 페르소나·시나리오가 존재하고 활성 상태인지 확인한 뒤 정책을 조합한다. DB 내부의 관계 참조에는 숫자 ID를 사용한다.

각 통화 조합은 페르소나 이미지와 약 10초 길이의 사전 등록 음성 미리듣기를 제공한다. 이미지와 음성 파일은 정적 콘텐츠로 등록하며 MVP에서 동적 voice 생성이나 voice 설정은 제공하지 않는다.

통화 기능을 구현하기 전에 `oncue-voice`의 Public STT·LLM·TTS provider와 provider adapter를 이용해 음성·대화 품질을 사전 검증한다. 이 검증은 개발용 Jupyter notebook에서 수행하며, 사용자에게 voice 설정 기능을 제공하는 것은 아니다.

### 사용자 입력

사용자는 예약 시 다음을 자유로운 문장으로 입력한다.

- `시나리오 컨텍스트`: 통화 배경, 이름, 관계, 말투 등
- `통화 목표`: 통화로 이루고 싶은 결과

각 입력 필드에는 필요한 정보를 알려주는 하나의 placeholder를 제공한다. 페르소나와 시나리오가 각각 제공하는 컨텍스트 placeholder는 UI에서 하나의 `시나리오 컨텍스트` 입력 안내로 합쳐 보여줄 수 있으며, `통화 목표`에도 하나의 placeholder만 제공한다. 제공자 정의의 `기본 지시사항`은 사용자에게 노출하지 않고 대화 정책 구성에 선택적으로 반영한다. 시나리오 적합성 검사는 하지 않고 사용자 입력을 의도된 컨텍스트로 간주한다.

### 예약

- 1회성 예약만 지원한다.
- 사용자 기기의 현지 시간대를 기준으로 예약한다.
- 백엔드는 현지 시간대와 UTC 시각을 함께 관리한다.
- 통화 5분 전까지 예약 생성·수정·취소가 가능하다.
- 사용자는 여러 예약을 등록할 수 있다.
- 통화 시간대가 겹치는 예약은 등록할 수 없다.
- 예약 시각은 통화 수신 목표 시각이며, 정시 수신을 보장하지 않는다.
- 실제 통화는 네트워크·기기 상태·푸시 전달에 따라 예약 시각 전후로 발생할 수 있다.

사용자는 예약된 통화 조합, 시나리오 컨텍스트, 통화 목표, 예약 시각을 변경할 수 있다. 페르소나 정의와 시나리오 정의는 변경할 수 없다.

### 통화

- 예약 시각에 한 번만 통화를 시도한다.
- 수신 대기 시간은 60초다.
- 60초 동안 응답이 없으면 `MISSED`로 종료하고 재시도하지 않는다.
- 기술적 연결 실패도 `FAILED`로 기록하고 재시도하지 않는다.
- 사용자가 응답하면 WebRTC 음성 연결을 시작한다.
- 시나리오 종료 조건을 달성하면 AI가 먼저 종료할 수 있다.
- 어떤 경우에도 최대 통화 시간은 5분이다.
- 사용자가 직접 종료할 수 있다.
- 음성과 대화 텍스트는 저장하지 않는다. 통화 상태, 시각, 종료·실패 사유 등 최소 메타데이터만 저장한다.

### 계정과 언어

- 한국 타깃은 Kakao 로그인만 제공한다.
- 해외 타깃은 X(구 Twitter) 로그인만 제공한다.
- Apple 로그인, 전화번호 로그인, 게스트 사용은 MVP에서 제외한다.
- 기기 언어가 한국어이면 한국어, 그 외에는 영어를 사용한다.

## 3. 아키텍처

### `oncue-mobile`

Flutter 공통 계층에 로그인, 통화 조합, 예약, 통화 상태 화면을 둔다. iOS 네이티브 계층은 PushKit과 CallKit을 연결하고, 통화 응답 후 WebRTC 클라이언트를 실행한다. Android를 추가할 때는 동일한 도메인·통화 상태 계약을 사용하고 Android의 푸시·통화 프레임워크를 별도 어댑터로 구현한다.

### `oncue-backend`

기능 중심의 단순한 모듈형 계층 구조로 사용자, 인증 identity, 통화 조합, 예약, 통화 상태를 관리한다. 각 기능은 controller·service·model·repository를 중심으로 구성한다. 외부 연동은 기능을 드러내는 `identity_provider`, `voice_server`, `safety_classifier` 같은 명시적인 경계를 사용한다. 헥사고날 아키텍처의 모든 계층·포트·어댑터를 일괄 적용하지 않는다.

예약 실행 시 페르소나와 시나리오의 기본 지시사항, 공통 안전 정책, 사용자 입력을 조합해 `대화 정책`을 만든다. 페르소나·시나리오에 별도 기본 지시사항이 없으면 기본 대화 정책을 사용한다. 대화 정책은 역할·대화 단계·통화 목표·금지 범위·종료 조건·언어·음성 ID를 포함하며, 실제 발화 문장을 고정하지 않는다.

백엔드는 음성 데이터를 중계하지 않는다. 보이스 세션을 제어하고, 모바일이 음성 연결을 요청할 때 사용자·예약·세션 권한을 확인해 짧은 만료 시간의 1회성 연결 토큰을 발급한다.

### `oncue-voice`

Python 기반의 범용 음성 세션, WebRTC 미디어, STT·LLM·TTS 연결과 외부 음성 서비스 provider를 담당한다. 백엔드가 전달한 대화 정책을 실행하되 페르소나·예약·사용자 데이터베이스에 직접 의존하지 않는다. 모델·음성 서비스별 포맷 변환은 보이스 모듈 내부에서 처리한다.

대화 runtime은 특정 provider SDK에 직접 의존하지 않고 provider 중립적인 `LlmProvider`, `SttProvider`, `TtsProvider` interface와 `ProviderFactory`를 사용한다. MVP에서는 하나의 Public provider 조합과 그 하위 모델·voice 설정을 먼저 검증하며, provider가 충분하지 않을 때만 같은 interface에 두 번째 Public provider adapter를 추가한다. v1.0.0 이후 Local provider를 연결할 수 있도록 확장 지점은 먼저 두지만, MVP에서 Local provider를 구현하거나 실행하지 않는다.

`oncue-voice/notebooks/voice_persona_scenario_evaluation.ipynb`는 보이스 서비스의 실제 application factory, `ConversationRuntime`, provider adapter와 정책 model을 사용한다. notebook 안에 STT·LLM·TTS 구현이나 별도의 대화 처리 모듈을 만들지 않는다. 실행 당시 실제 runtime에 전달된 최종 대화 정책은 정책 스냅샷으로 로컬 평가 artifact에 저장한다.

백엔드와 보이스 사이에는 REST 기반 세션 생성·종료·상태 전달 제어 API를 둔다. 모바일과 보이스 사이의 실제 음성 채널은 WebRTC를 사용한다.

### 통화 실행 흐름

1. `oncue-voice`가 provider adapter와 대화 runtime을 사용해 음성·대화 품질을 사전 검증한다.
2. 모바일이 백엔드에 `personaKey`, `scenarioKey`, 컨텍스트, 목표, 현지 예약 시각을 전송한다.
3. 백엔드가 페르소나·시나리오의 개별 존재·활성 상태와 예약 제약을 검증한다.
4. 규칙 기반 안전 검사 후 위험 신호가 있을 때만 LLM 안전 판정을 실행한다.
5. 안전 판정을 통과하면 예약을 저장한다.
6. 예약 시각에 백엔드가 대화 정책과 보이스 세션을 준비한다.
7. VoIP Push에는 전체 컨텍스트나 장기 자격 증명 대신 통화 식별자만 전달한다.
8. 모바일은 수신한 통화를 CallKit에 보고한다.
9. 사용자가 응답하면 모바일이 백엔드에 연결 권한을 요청한다.
10. 백엔드는 권한을 검증하고 1회성 WebRTC 연결 토큰을 발급한다.
11. 모바일과 보이스가 토큰을 검증한 뒤 직접 WebRTC로 연결한다.
12. 보이스가 대화 정책에 따라 실시간 대화를 실행하고 상태 이벤트를 백엔드에 전달한다.

## 4. 안전 및 악용 방지

통화 안전 정책은 예약 생성·수정 시점과 실제 통화 중 모두 적용한다.

### 예약 시점

1. 시나리오 컨텍스트와 통화 목표에 규칙 기반 검사를 적용한다.
2. 금융·송금, 비밀번호·OTP·인증번호, 실제 기관·인물 사칭, 협박·긴급 송금, 개인정보 탈취와 관련된 위험 신호가 있으면 차단한다.
3. 규칙에서 위험 신호가 발견된 경우에만 LLM 안전 판정을 요청한다.
4. LLM 결과가 위험하거나 안전 판정 서비스가 실패·불확실하면 fail-closed로 예약을 차단한다.
5. 차단 결과는 예약 요청에 대한 앱 응답으로 즉시 안내한다.
6. 차단 Push 알림은 MVP에 포함하지 않고 v1.0.0 이후 추가한다.

### 통화 중

- 실제 인물의 음성을 복제하지 않는다.
- 사용자가 제공한 이름·관계·말투 정보는 대화 내용과 표현 방식에만 반영한다.
- 금융 정보·인증 정보·송금·외부 메시지 발송·계정 변경 같은 행동을 요청하거나 실행하지 않는다.
- 위험한 대화 목적이 감지되면 해당 요청을 거부하고 필요할 경우 통화를 종료한다.
- 음성이나 대화 텍스트를 저장하지 않으므로 안전 이벤트에는 최소한의 사유 코드와 통화 식별자만 남긴다.

## 5. 상태 모델

```text
SCHEDULED → PREPARING → RINGING → CONNECTING → IN_CALL
     ↓          ↓           ↓          ↓           ↓
CANCELLED    FAILED      MISSED      FAILED   COMPLETED
                                                  ├─ USER_ENDED
                                                  ├─ SAFETY_BLOCKED
                                                  └─ TIME_LIMIT_REACHED
```

통화 5분 전 예약을 잠그며 이후 수정·취소를 거부한다. 모든 상태 전이는 중복 이벤트를 안전하게 처리해야 한다. `MISSED`, `FAILED`, `SAFETY_BLOCKED`에는 자동 재시도를 적용하지 않는다.

## 6. 완료 기준

- Kakao·X 로그인으로 사용자를 식별할 수 있다.
- 기기 언어에 따라 한국어·영어가 자동 선택되고, 그 외 언어는 영어로 처리된다.
- 네 개 통화 조합이 이미지·10초 음성 미리듣기와 함께 노출된다.
- 사용자가 컨텍스트와 목표를 자유롭게 작성해 1회성 통화를 예약할 수 있다.
- 5분 전 마감, 중복 예약 차단, 현지 시간 처리가 동작한다.
- 백그라운드·잠금 상태에서 CallKit 수신 화면이 표시된다.
- 응답 후 모바일과 보이스가 인증된 WebRTC로 연결된다.
- 시나리오 정책, 최대 5분, 미응답 60초, 실패 무재시도가 동작한다.
- 위험 예약은 규칙 검사와 선택적 LLM 판정을 거치며, 판정 실패 시 차단된다.
- 음성과 대화 텍스트가 저장되지 않는다.
- 통화 기능 구현 전에 하나의 Public provider 조합에 대해 음성·말투·시나리오 목표를 수동 평가할 수 있다.
- provider adapter를 통해 같은 Public provider의 하위 모델·voice 설정을 A/B 비교할 수 있다.
- 평가 실행의 정책 스냅샷과 합성 테스트 결과를 로컬 artifact로 다시 확인할 수 있다.
- 보이스 서버가 백엔드 데이터베이스나 장기 자격 증명에 접근하지 않는다.

## 7. 후속 범위

v1.0.0 이후 다음을 계획한다.

- 관리자가 페르소나를 등록·수정·공개하는 관리자 페이지
- 페르소나와 시나리오의 N:M 관계
- 반복 예약
- 안전 차단 Push 알림
- 사용자 voice 설정 및 설정 기반 미리듣기 생성
- provider가 충분하지 않을 때 두 번째 Public provider를 비교하기 위한 추가 adapter
- Android 모바일 구현
- 사용자가 직접 페르소나를 생성하는 기능

- 정적 이미지·음성 파일 저장소와 CDN
- 데이터베이스와 예약 실행 워커
- iOS 실제 기기·백그라운드·잠금 상태 검증 환경
